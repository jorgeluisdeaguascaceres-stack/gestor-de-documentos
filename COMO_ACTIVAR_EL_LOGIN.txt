   ACTIVAR USUARIO Y CONTRASENA EN INTERNET  (5 minutos)
   Gestion Documental y Nomenclatura Automatizada
===============================================================

QUE HACE ESTO
-------------
Ahora tu programa queda detras de un "portero". Nadie vera la
aplicacion en internet sin escribir usuario y contrasena. La clave
se revisa en el SERVIDOR, no en el navegador, por eso NO se puede
saltar (ni escondiendo la ventana, ni con F12, ni entrando directo
a una direccion interna).

No hay que instalar nada nuevo. Tu programa sigue igual: el portero
solo se pone delante.


PASO 1 - COPIAR LOS DOS ARCHIVOS
--------------------------------
En la carpeta de tu proyecto (la misma donde esta "server.js"),
copia los archivos que te entrego:

   auth-gate.js      <- el portero
   package.json      <- reemplaza el que tenias

(usuarios.json es opcional, ver Paso 3 opcion B)

IMPORTANTE: NO borres ni modifiques tu server.js. Sigue siendo el
que hace todo el trabajo.


PASO 2 - SUBIR AL SERVIDOR
--------------------------
Si publicas con GitHub, sube los cambios:

   git add auth-gate.js package.json
   git commit -m "Acceso con usuario y contrasena"
   git push

Si subes los archivos a mano en el panel de Render, sube esos dos
archivos a la carpeta principal del proyecto.


PASO 3 - PONER TUS USUARIOS Y CLAVES
------------------------------------
OPCION A (RECOMENDADA - las claves no quedan en el codigo):

  1. Entra a https://dashboard.render.com
  2. Abre tu servicio "gestor-documentos"
  3. Menu izquierdo: Environment  ->  Add Environment Variable
  4. Agrega estas dos:

     Nombre : APP_USERS
     Valor  : jorge:MiClaveSegura2026,auditor:OtraClave2026

     Nombre : SESSION_SECRET
     Valor  : (cualquier texto largo al azar, 30+ caracteres,
               por ejemplo: k7Xp2mQ9wRt4vZs8nLb3jHc6yEa1dFg5)

  5. Guarda. Render reinicia solo.

  Formato de APP_USERS:  usuario:clave,usuario:clave
  - separa usuario y clave con dos puntos  :
  - separa una persona de otra con coma    ,
  - sin espacios
  - puedes poner tantas personas como quieras

OPCION B (mas simple, menos segura):
  Edita el archivo usuarios.json que te entrego, cambia las claves
  y subelo junto con los demas. Sirve, pero las claves quedan
  escritas dentro del proyecto.

Si no configuras nada, el portero arranca con la clave inicial
  usuario: jorge   clave: Cambiar2026*
y te avisa en pantalla que la cambies. No la dejes asi.


PASO 4 - VERIFICAR EN EL PANEL
------------------------------
En Render, seccion Settings, revisa que el comando de arranque sea
uno de estos:

   npm start          (correcto, ya apunta al portero)
   node auth-gate.js  (tambien correcto)

Si dice "node server.js", cambialo por "node auth-gate.js".
Si no lo cambias, el portero nunca se activa.


PASO 5 - PROBAR
---------------
1. Abre gestor-documentos-2voy.onrender.com
2. Pulsa Ctrl+F5 para que no cargue la pagina guardada.
3. Debe aparecer la pantalla "Acceso restringido".
4. Escribe tu usuario y clave -> entra el programa normal.

OJO: la primera visita despues de publicar puede tardar hasta un
minuto (el plan gratuito de Render apaga el servidor cuando nadie
lo usa). Espera y refresca.


CERRAR SESION
-------------
Entra a la direccion de tu app agregando  /__salir  al final.
Ejemplo:  gestor-documentos-2voy.onrender.com/__salir

Si quieres un boton "Salir" dentro de la pagina, avisame y te lo
dejo puesto en el encabezado (necesito tu index.html).

La sesion se cierra sola a las 8 horas. Para cambiarlo, agrega la
variable SESSION_HOURS con el numero de horas que quieras.


SI ALGO SALE MAL
----------------
"Sigue entrando sin pedir clave"
   -> El comando de arranque todavia es "node server.js".
      Cambialo a "node auth-gate.js" (Paso 4). Luego Ctrl+F5.

"Dice: El programa esta iniciando"
   -> Tu server.js tarda en levantar. Espera 30 segundos y refresca.

"Pagina en blanco o error 502"
   -> Revisa los Logs en Render. Si aparece "Cannot find module",
      tu server.js necesita librerias (express, multer, pdf-lib...).
      Mandame tu server.js y te completo la lista de dependencias.

"No encontre el archivo de tu servidor"
   -> Tu archivo principal no se llama server.js. Agrega la variable
      APP_ENTRY con el nombre real, por ejemplo: app.js


LO QUE FALTA (importante para datos de pacientes)
-------------------------------------------------
Esto ya resuelve la puerta de entrada, y es un salto grande frente
a lo que tenias. Pero para historias clinicas en internet todavia
conviene:

  - Claves guardadas cifradas, no en texto plano.
  - Registro de quien entro, que subio y que consulto (auditoria).
  - Permisos por rol: quien puede borrar y quien solo consultar.
  - Respaldo automatico de los PDF.
  - Que los archivos PDF tambien exijan sesion para descargarse.

El ultimo punto depende de como tu server.js entrega los archivos.
Si me mandas server.js, index.html y app.js lo reviso y te lo dejo
completo.
